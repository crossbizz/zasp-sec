# Deploy the offline CLI with Intune

This user-context Win32 application gives a pilot group the local scan and private HTML report on Windows. It installs the CLI under the employee's local application data. Fleet enrollment, Windows runtime hooks, central collection and Windows service installation require separate implementations.

1. Build the Windows `zaspctl.exe` from [the CLI module](../../../cmd/zaspctl/go.mod) for the pilot's x64 or ARM64 architecture. Sign the executable through your approved Authenticode release pipeline and time-stamp it. Verify the signature on Windows with `signtool verify /pa /all zaspctl.exe`. Obtain the signed artifact's approved SHA-256 and expected signing certificate thumbprint from release metadata.
2. Prepare a new release directory using `node stage.mjs SIGNED_EXE RELEASE_SHA256 SIGNER_THUMBPRINT NEW_DIRECTORY`. This checks the PE architecture and pinned file digest and generates a matching installation manifest and Intune detection script. The Windows installer independently verifies the Authenticode chain and signer. Sign the generated detection script and installer with your approved PowerShell publishing certificate if the tenant requires signed scripts.
3. Use the Microsoft Win32 Content Prep Tool on the release workstation. Run `IntuneWinAppUtil.exe -c NEW_DIRECTORY/input -s Manage-ZaspCli.ps1 -o OUTPUT_DIRECTORY -q`. Keep the output directory outside the input. Assign the resulting Win32 app to the test group with **Install behavior → User** and an architecture requirement matching the release.
4. Use `powershell.exe -NoLogo -NoProfile -NonInteractive -File Manage-ZaspCli.ps1 -Action Install` for installation and the same command with `-Action Uninstall` for removal. Use `Detect-ZaspCli.ps1` as the custom detection rule in the same user context. Detection checks signer, valid chain and the exact digest. No PATH change, sign-in, remote sync or scheduled file scan occurs during installation.
5. From PowerShell, run `& "$env:LOCALAPPDATA\Zasp\CLI\zaspctl.exe" addons inventory --local --scope project --project . --harness all --report-html .\inventory.html`. A developer may opt into findings-only submission separately.
6. Prove delivery on a pilot Windows machine with the actual certificate, Intune policy and selected account. Verify detection, a scan with two distinct profile roots, rejection of an altered package, and upgrade to the new package. Reassign the prior signed version to roll back. An old uninstall assignment preserves a newer digest and employee reports.

The portable fixture test checks release staging with `node --test stage.test.mjs`. Actual Authenticode verification runs through Windows, and Intune packaging and assignment require the customer's signed release and managed tenant.
