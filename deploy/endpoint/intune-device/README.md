# Managed Windows inventory pilot

The Windows agent registers an assigned device, sends signed health and uploads an employee's local skill and MCP installation metadata. It supports one assigned Windows SID and one personal or managed collection scope per enrollment. The Windows agent has no pre-tool adapter. Fleet policy acknowledgment stays false. Windows inventory cannot establish execution, enablement, or target effect.

## IT deployment

1. Build `go -C services/endpoint-agent build -trimpath -o zasp-device-windows.exe ./cmd/zasp-device-windows` for Windows amd64 or arm64. Authenticode-sign it with the organization's approved release identity, publish the SHA-256 digest of the signed bytes and the signer thumbprint. On Windows run `Stage-Device.ps1 -SignedExecutable <file> -AgentSHA256 <digest> -SignerThumbprint <thumbprint> -NewOutput <new-directory>`. It validates both pins. Use Microsoft's IntuneWinAppUtil to package the staged `input` directory with `Manage-Device.ps1` as the setup file. Use the generated standalone detection script. Sign the deployment scripts with the organization’s approved signer when the managed Windows execution policy requires signed PowerShell.
2. Deploy the [employee-context CLI](../intune-cli/README.md). Assign the new device Win32 app using **System** install behavior and **64-bit Windows PowerShell**. Set `Manage-Device.ps1 -Action Install -AgentSHA256 <digest> -SignerThumbprint <thumbprint> -EmployeeSID <SID> -Scope personal`. Select `managed` for managed inventory. The two scheduled tasks run every five minutes. The employee scanner runs only with the assigned user's interactive token. The LocalSystem transport reads a fixed file whose DACL grants that user write-data. It rejects alternate file links or reparse points and never opens paths contained in the report.
3. The installer prints a per-device Ed25519 public key. Retrieve it over the existing authenticated MDM management channel. Re-running `zasp-device-windows.exe init-device-key` in LocalSystem context returns the same public key. Create a dedicated Environment `sync_endpoint` credential and pre-register the public key, transport token ID, cohort and independently held issuer public key using the Devices enrollment screen. Use separate credentials for every device.
4. Provision the resulting nonsecret `device.json` under `%ProgramFiles%\Zasp Inventory Device`, with owner SYSTEM or Administrators and inherited read-only employee access. The binding and SID must exactly match registration and deployment. Example:

   ```json
   {"origin":"https://zasp.example.com","binding":{"organization_id":"ORG","workspace_id":"WORKSPACE","environment_id":"ENVIRONMENT","device_id":"DEVICE","credential_generation":1},"scope":"personal","assigned_sid":"S-1-5-21-111-222-333-1001"}
   ```

5. Through a separately authenticated per-device secret-delivery service running as LocalSystem, pipe the unique transport PAT from the provider directly to `zasp-device-windows.exe provision-token` on standard input. Keep secrets out of package files, Intune command arguments and task transcripts. User-profile DPAPI seals the transport secret, signing seed and local queue under LocalSystem with distinct purposes. This is a software-backed key. The generic installer carries no fleet-wide enrollment authority.
6. Start the employee scan after the assigned user signs in, then the device sync task. `zasp-device-windows.exe status` as LocalSystem returns the device ID, last confirmed heartbeat and pending snapshot count. The assigned employee can run `zaspctl device status` or `zaspctl device doctor` to read a limited LocalSystem-published health summary from the 64-bit HKLM registry. It reports inventory-only coverage and considers telemetry stale after 15 minutes. Inspect central Devices → device → Local inventory. Windows sends only HMAC installation and partition references, manifest digests and completeness. The queue preserves a prior complete snapshot across a later partial scan and retries rejected uploads. A quiet or unsigned-in laptop retains its historical evidence. Task scheduling and central observation are separate statuses.
7. Retire the device server-side before removing the managed app. The next exchange will be denied. Use the same release pins with `Manage-Device.ps1 -Action Uninstall` to remove both scheduled tasks, the executable, the employee collector, its plaintext handoff and its health summary. The sealed queue and protected credentials remain for the organization's controlled recovery. Archive required evidence, then remove retained data using IT's offboarding process. Provision a new key, credential, clean state and assignment when changing employee or rotating the device identity.

## Validation

The portable integration test sends real device signatures over TLS and checks retry, retained partial inventory, de-duplication, absence of policy acknowledgment, and rejection after retirement. The native Windows CI tests exercise profile-bound DPAPI tamper and purpose checks, access-control descriptor validation, PowerShell parsing and rejection of unsigned packages. A live release requires an approved Authenticode signer, real Intune assignment, the operator's per-device secret-delivery channel and a signed-in employee. Confirm install, upgrade, user-context scan, offline recovery and uninstall on the targeted Windows configurations before promoting the pilot.
