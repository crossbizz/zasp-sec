# Zasp SDKs

Client libraries for the Zasp API in four languages. They are generated by
[Fern](https://buildwithfern.com) from the API contract, `openapi/openapi.yaml`,
with the configuration in `fern/generators.yml`.

| Language | Directory | Install from source | Smoke test |
| --- | --- | --- | --- |
| TypeScript | `sdks/typescript` | [README](typescript/README.md) | `tests/smoke.test.mjs` |
| Python | `sdks/python` | [README](python/README.md) | `tests/test_smoke.py` |
| Go | `sdks/go` | [README](go/README.md) | `smoke_test.go` |
| Java | `sdks/java` | [README](java/README.md) | `src/test/java/SmokeTest.java` |

None of them is published to a package registry. You install them from this
repository.

## What they cover

The SDKs hold the 116 operations an API token may call, in 24 groups such as
`agents`, `findings`, `guardrails`, `integrations` and `tests`. The other 74
operations of the API need a browser session (sign-in, identity
administration, API token management, compliance exports) and are in the API
reference only.

Every client needs two values:

- the address of your Zasp deployment, for example `https://zasp.example.com`;
- an API token. Create one in the product under API Access. A token that reads
  the Environment is enough for the read operations.

The clients read the token from the environment variable `ZASP_API_TOKEN` when
you do not pass one.

List operations return a pager. Iterating it requests the next page with the
cursor the API returned.

## What is generated and what is not

Everything in these directories is written by the generator, except:

| Language | Hand-written files |
| --- | --- |
| TypeScript | `package.json`, `tsconfig.json`, `README.md`, `tests/` (the generator writes `src/` only) |
| Python | `pyproject.toml`, `README.md`, `tests/` (the generator writes `src/zasp/` only) |
| Go | the files listed in `go/.fernignore` |
| Java | the files listed in `java/.fernignore` |

Do not edit a generated file. Change `fern/generators.yml`,
`fern/openapi-overlays.yml` or `fern/scripts/build-openapi-overrides.mjs` and
generate again.

## Generate again

After a change to `openapi/openapi.yaml`:

```bash
npm run sdk:generate
```

That uses Fern's cloud generators and needs `FERN_TOKEN`. To run the generators
on your machine instead, which needs Docker and no token:

```bash
npm run sdk:generate -- --local
```

Then check the result:

```bash
npm run sdk:test
```

`fern/README.md` describes both, and how the SDKs in this directory were
generated.

## Test fixtures

`fixtures/responses.json` holds contract-shaped responses with made-up values.
Each smoke test starts a local HTTP server that serves them, and checks the
request the client sent: the path, the bearer header, the cursor of the second
page, the request body, and the exception for a `401`.
