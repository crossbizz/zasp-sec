## Implemented boundary

Three private release61 tables retain immutable account revisions, policy revisions, and exact mutation requests/responses. Each has tenant keys, authority-only FORCE RLS, no direct service-role table grants, and immutable update/delete/truncate guards. Account revisions contain a scoped credential reference and SHA-256 digest, never secret bytes. Policies approve exact OpenRouter provider/model/account profile/credit unit, request policy version and token limit, maximum total tokens/cost, UTC effective/expiry times, canonical IDs and digest, and creator/fresh-auth evidence. Limits use the existing 12,000-token and 1,000,000,000,000-nano-credit domain ceilings, 4,096 output tokens, and at most 720 elapsed hours of validity.

Only the discovery admin principal can call `pricing_admin`. It requires active organization_admin/security_admin membership and explicit `view` plus `manage_identity` permission on the exact tenant scope, fresh authentication, expected policy/account versions, and canonical idempotency identity. Create/version/disable append history and an admin audit entry. Replay must match the exact request and current retained policy/account state; it cannot revive an old version. A shared schema fence precedes Organization serialization, ordered policy rows and account rows. Identity/scope row reads are NOWAIT so a concurrent safety writer is not blocked by an inverted lock order. Audit-key waits recheck current identity, permission, freshness, policy expiry and readiness before commit.

Only the planner worker principal can call `pricing_lookup`. It takes the same schema/Organization/policy/account order, rejects absent or ambiguous identities, and binds the exact current policy/account revision, scoped credential digest/reference, provider/model/profile/unit, request policy version, token limit and retained body digest. The original JSON body is duplicate-key checked before jsonb conversion and must have the closed prepared-request structure, separated system/user messages, strict structured response, and provider data-collection denial. Current expiry/readiness is rechecked after waits. Lookup performs no reservation, journal, planning or provider work.

The internal Go repository rejects duplicate/unknown/null fields, malformed IDs/digests/times, out-of-domain versions and byte limits before SQL. It independently verifies the returned canonical IDs, digest, exact state/version postconditions, body binding and cost-policy pin. Its private worker adapter binds the existing prepared request and actual retained credential hash, then rechecks one-shot/configuration/credential/cancellation state after lookup. It returns the existing verified-bound type as an approved ceiling. The historical/default `PlannerBudget()` remains unpriced and unchanged.

Policy/admin wire limits are 8,192 bytes. Prepared bodies are at most 65,536 UTF-8 bytes; lookup requests permit 524,288 bytes for JSON escaping plus metadata. Returned policy/bound responses use the same 8,192-byte closed decoder. SQL and Go exact body-boundary tests cover 65,536 acceptance and 65,537 refusal without mutation.
