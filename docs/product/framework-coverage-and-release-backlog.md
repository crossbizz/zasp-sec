# Zasp framework coverage and release security backlog

**Decision, November 22, 2026.** Publish a complete index for OWASP Agentic 2026, OWASP LLM 2025, OWASP LLM 2026 and a pinned MITRE ATLAS release. Give each category an owner, an applicability decision and a link to available evidence. Build controls first where a customer can make a decision or verify an outcome. Production promotion also requires fresh advisory checks against the exact software Zasp ships.

**Baseline.** At `840fd1f0`, 29 posture rules reference five OWASP Agentic categories, five OWASP LLM 2025 categories and four ATLAS techniques. Selected NIST, ISO and EU AI Act references are also in production code. Customers can open finding details, select a control under **Compliance** and export evidence. The laptop scanner emits its own rule IDs. The production release gate always stops after its checks. The tasks below describe proposed work on this branch. ## OWASP implementation tickets

### Agentic Applications 2026

Keep and revalidate current references for ASI02 Tool Misuse and Exploitation, ASI03 Identity and Privilege Abuse, ASI04 Agentic Supply Chain Vulnerabilities, ASI05 Unexpected Code Execution and ASI10 Rogue Agents. The following five categories lack posture references. Each row defines a bounded test a customer could inspect. [OWASP Agentic 2026](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/)

| Category | Implementation and proof |
|---|---|
| ASI01 Agent Goal Hijack | Bind the declared task to a scoped action and destination. Compare a permitted ticket update with an out-of-purpose action in staging. Show the task, action, decision and outcome together. A mismatch establishes deviation. Its cause remains open. |
| ASI06 Memory & Context Poisoning | Record authorized memory writes and subsequent reads by writer, tenant, record version and digest. Test a trusted synthetic record and an unapproved replacement. Show which version was recalled. Claims about influence require an observed downstream effect. |
| ASI07 Insecure Inter-Agent Communication | Instrument sender, intended recipient, audience, authentication and freshness on a supported handoff. Deliver a valid handoff and verify rejection of an expired or wrong-recipient handoff. Surface uninstrumented channels as unknown. |
| ASI08 Cascading Failures | Correlate parent/child operations, retries, fan-out limits and circuit-breaker outcomes. In a two-agent fixture, induce a benign downstream outage and verify bounded retries and independent final state. |
| ASI09 Human-Agent Trust Exploitation | Bind the exact action, recipient, scope and expiry displayed for approval to the executed request. Show that an approved request succeeds and changing the recipient requires fresh approval. The receipt establishes what was displayed and authorized. |

### LLM Applications 2025 and 2026

Create **separate catalogs for both editions**. Only Prompt Injection and Sensitive Information Disclosure retain their numbers. The middle column is a migration aid that requires semantic review. The new Hidden Context Exposure category expands the older system-prompt risk. [OWASP LLM 2025](https://genai.owasp.org/llm-top-10/) · [OWASP LLM 2026 edition and download](https://genai.owasp.org/resource/owasp-genai-llm-top-10-2026/)

| 2025 ID and risk | 2026 ID and risk | Work to accept the mapping |
|---|---|---|
| LLM01 Prompt Injection | LLM01 Prompt Injection | Revalidate existing posture and probe references against each edition. Show when an observed input and a runtime outcome are available. |
| LLM02 Sensitive Information Disclosure | LLM02 Sensitive Information Disclosure | Revalidate existing mappings. Use synthetic sensitive data for a controlled egress test and show the observer’s scope. |
| LLM03 Supply Chain | LLM04 Supply Chain | Remap existing skill/MCP posture findings. Verify that the same version-specific review carries the correct ID in each report. |
| **LLM04 Data and Model Poisoning** | **LLM05 Data and Model Poisoning** | Collect signed source/version approval for model or dataset promotion. Verify a trusted version and a rejected unapproved change. A provenance failure establishes an integrity risk. |
| LLM05 Improper Output Handling | LLM10 Improper Output Handling | Review existing references. Exercise a typed output boundary with valid and invalid synthetic values and verify the downstream result. |
| LLM06 Excessive Agency | LLM03 Excessive Agency | Revalidate permissions and action-scope rules. Report effective permissions separately from exercised permissions. |
| **LLM07 System Prompt Leakage** | **LLM08 Hidden Context Exposure** | Test synthetic markers in a system prompt and separately in private retrieved context. Inspect only the required test output. Grade the two scopes independently and retain no customer prompts by default. |
| **LLM08 Vector and Embedding Weaknesses** | **LLM09 Vector and Embedding Weaknesses** | Instrument a retrieval adapter with collection, tenant and document ACL decisions. Prove authorized retrieval succeeds and a second synthetic tenant cannot retrieve the same marker. Access inventory alone cannot establish retrieval isolation. |
| **LLM09 Misinformation** | **LLM07 Misinformation** | Start with one workflow backed by an authoritative test record. Verify grounded answers and an abstain/review outcome when support is absent before a consequential action. Limit the claim to the tested workflow and ground truth. |
| **LLM10 Unbounded Consumption** | **LLM06 Unbounded Consumption** | Enforce per-run token, cost or action budgets on a metered route. Test normal completion, an over-budget stop, retried requests and a missing meter. Reconcile the final count with the independent meter. |

Bold rows are missing from Zasp’s 2025 posture catalog. All ten 2026 rows need initial review. The same test may support references in both editions when its evidence satisfies both definitions. Keep that single test identity in the report.

## First customer acceptance run

A developer scans a local skill offline. The CLI identifies an unpinned dependency, explains ASI04, shows the affected file and recommends verifying and pinning the resolved version. The developer shares findings only. AppSec opens that exact skill digest, filters Compliance by **OWASP Agentic 2026 → ASI04**, and exports the evidence. The report identifies a static scan. A later governed tool action adds a session record. A staging control test adds a separate verification record if an independent target confirms the outcome. A device with no recorded action continues to show unknown usage.

Reuse `POST /api/v1/addon-scans`, `GET /api/v1/addon-scans/{id}`, `POST /api/v1/runtime/action-decisions`, `POST /api/v1/runtime/actions/{actionId}/outcomes` and the Compliance controls, evidence and export routes. Extend their schemas additively, version strict local upload formats when necessary, retain the original edition on persisted exports and verify the OpenAPI contract and existing SDK clients. Start a new adapter for memory or retrieval only after defining the minimum receipt, access boundary and supported provider. [Registered API operations](../../services/platform/apiserver/composition.go) · [API contract](../../openapi/openapi.yaml) · [V2 customer journeys](feature-v2-final-implementation-plan.md)

**Suggested milestones.** The release owner can accept tasks 1–3 once a clean candidate is promoted in staging and an affected candidate is refused. The first customer demonstration is the offline-to-export ASI04 journey built with tasks 4–6 and the corresponding parts of task 9. Next, demonstrate one purpose-bound action, one changed-approval refusal and one enforced budget with corroborated outcomes. Expand into retrieval, memory, handoffs and model provenance as adapter receipts become available. Keep each unverified surface visible until its acceptance run passes.
