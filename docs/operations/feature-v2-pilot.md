# Managed AI security pilot

Use this page to decide which controls to enable for a pilot Environment. A native package test, a managed-device acknowledgment and an independently observed change to a target answer different questions. Record the build, OS, harness, browser and policy revision with each pilot result.

| Surface | What the release exercises | What the pilot owner must verify |
| --- | --- | --- |
| Laptop and repository add-ons | Offline inventory, matching and edited manifests, partial scans, bounded static analysis, findings-only sharing, CI signatures, reviews and affected installations. The scanner benchmark uses seven labeled benign fixtures. | Select the actual personal, project and managed roots. Compare two copies, edit one, and verify the review and device impact. Track installation, load and execution as separate observations. |
| macOS endpoint | The native CI job creates a temporary System Keychain item, runs the daemon and employee hook under different privileges, verifies signed decisions and removes the credential. The local signed TLS and PostgreSQL tests cover the management path. | Sign and notarize the package with the release identity. Use Jamf to assign it, record the exact Claude Code build and hook precedence, exercise enrollment and removal, measure latency and verify ticket write/readback during concurrent work. |
| Windows endpoint | Native CI exercises DPAPI, file access controls, signed inventory transport, key and spool permissions, and unsigned installer rejection. | Assign the signed package through Intune, confirm the expected employee SID, and rehearse upgrade, offline recovery, retirement and uninstall. Windows reports inventory-only coverage. |
| Managed Chrome and Edge | Managed-origin policy, private-profile suppression, signed origin/day records, scoped admission, profile health and retirement. The browser profile can report independently of an endpoint agent. | Verify the signed extension, effective browser policy and individual profile binding on each listed browser/build. A reported origin indicates a visit. Action or upload prevention requires a separately verified integration. |
| Gateway and Python | Scoped workload binding, preserved legacy gateway sessions, before-action admission and outcome receipts, signed or supervised isolation with explicit readback. Integration tests use real SDKs with synthetic local upstreams. | Route an approved workload to its actual upstream, verify the instrumented tool and session, and exercise allow, deny, expiry and release. Record principal, session and decision receipts. |
| Evidence and guardrails | PostgreSQL retains the source, Neo4j projects scoped observed relationships, and reviewed purpose drift can lead to replay and staged policy promotion. A pending graph projection leaves the source decision available. | Check what was observed, which values the caller reported and which were unknown. Review the eligible denominator, attributed actions, truncation and target readback before expanding a cohort. |
| Private scanning | A fresh authorized request binds upload permission to the Environment, digest, size, worker and retention mode. Retained scans opt into a 24-hour deadline. | Verify the configured private origin, collection mode, S3/KMS permissions, versioning and cleanup in a disposable staging account. Save exact-version deletion readback and exercise an interrupted cleanup. |
| Claude Enterprise provider hook | The implementation plan gates this adapter on access to an enabled organization. | Verify the organization's signing, tenancy, timeout and retry contract before implementing or enabling this provider adapter. |

## Release and deployment evidence

- **Native runner evidence.** The Linux, macOS and Windows jobs passed on commit `f29556b3`. That result covers the code paths listed in the workflow. For a later candidate, use that candidate’s own check results. [Native CI run](https://github.com/crossbizz/zasp-sec/actions/runs/44984770358)
- **Database and API.** Run `scripts/test-feature-v2-upgrade.sh` from a checkout with its predecessor in Git history, Go, Node and PostgreSQL 18 available. The script creates its own temporary cluster, upgrades a populated database, compares its catalog to a fresh install and exercises the installed product paths. Environment access, credentials and graphs for deployed customers are separate from this test.
- **Pilot rollout.** Enroll the selected devices, start in monitor, issue one signed canary revision and check its acknowledgment. Record allowed and protected action IDs with independent recorder evidence. Retain offline devices in the rollout denominator. A rollback publishes a higher revision and remains pending on disconnected devices until acknowledgment.
