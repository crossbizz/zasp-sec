# Infrastructure providers

Use the production AWS release for the complete application. It can independently use OpenBao for connector credentials or recovery signatures and R2 for encrypted offsite archives. The local and Kubernetes evaluation profiles retain their existing emulators. New CLI configurations select the VPS profile. Its component commands install and check the independent services described below. The complete customer-data release still requires the AWS production profile. [VPS first deployment](vps-first-deployment.md)

EKS workload identity, remaining startup secret delivery, production search and other managed dependencies still apply. Optional SSE-S3 covers discovery/recovery evidence and SSE-SQS covers the audit-export queue pair. | [Helm overlay](../../deploy/examples/infrastructure-providers/hybrid-openbao.values.yaml), [matching Terraform](../../deploy/examples/infrastructure-providers/hybrid-aws.tfvars), [R2 archive writer](../../deploy/examples/infrastructure-providers/r2-backup-writer.env) |

## Settings and authority

The API and worker check the infrastructure selectors at startup. Configure each workload that uses the capability. An unavailable provider fails the corresponding operation or readiness probe. Selecting an infrastructure provider does not move data or change customer discovery role assumption, connector scope, or tenant authorization.

| Capability | Settings and supported values | Scope |
| --- | --- | --- |
| General platform secrets | `ZASP_SECRETS_PROVIDER=aws-secrets-manager` or omit | Existing platform secret dependencies. For selected API and discovery startup settings, a sibling `_FILE` accepts a protected file projected by a workload credential manager. |
| Connector secrets | `ZASP_CONNECTOR_SECRETS_PROVIDER=aws-secrets-manager\|openbao` | API runtime creation/consumption of OAuth records and supported integration credentials, and discovery reads. Each workload has its own token. Configure a dedicated KV v2 mount, TLS, credential paths and a matching namespace. [Secret migration](openbao-connector-secrets.md) |
| Recovery signatures | `ZASP_RECOVERY_SIGNING_PROVIDER=aws-kms\|openbao` | The backup worker signs and the restore worker verifies. Keep historical KMS or Transit authorities for the manifests that identify them. OpenBao Transit requires a named ECDSA P-256 key. [Signing and verification](recovery-signing-providers.md) |
| Core evidence | `ZASP_EVIDENCE_PROVIDER=s3`; `ZASP_EVIDENCE_ENCRYPTION=aws-kms\|provider-managed` | Optional SSE-S3 applies to discovery and recovery evidence. Existing version, content-digest and owner checks still run. Other archives and export stores retain their own policies. [S3 migration](evidence-encryption.md) |
| Job queue | `ZASP_QUEUE_PROVIDER=sqs`; `ZASP_AUDIT_EXPORT_QUEUE_ENCRYPTION=aws-kms\|provider-managed` for the audit export publisher and consumer | SQS keeps its durable outbox, fencing, redrive and visibility behavior. The optional encryption change covers only the audit work queue and its DLQ. Other SQS queues retain existing settings. [Queue encryption and rollback](audit-export-queue-encryption.md) |
| Offsite archive | `ZASP_BACKUP_PROVIDER=local\|s3\|r2` on the operator host | Existing ordinary local archives remain available. Remote uploads use a public recipient certificate, provider-scoped credentials, create-only writes and full ciphertext SHA-256 read-back. Restore requires the original receipt and private decryption material. [Backup configuration](offsite-backups.md) |
| Nango | `nango.externalNamespace` and `nango.storageSecretName` on the production chart | Empty external namespace keeps the bundled installation. A separate release serves its private TLS endpoint, stores its own credentials and depends on a dedicated verified-TLS PostgreSQL database. [Installation](independent-nango.md) |

Cloudflare Secrets Store makes stored values available to the associated Cloudflare service. The management API cannot retrieve the value for a Go process on a VPS. The documented integrations are Workers and AI Gateway, and the service does not provide the recovery sign/verify API needed here. Use scoped OpenBao or AWS credentials for these paths. [Cloudflare compatibility](https://developers.cloudflare.com/secrets-store/) · [Stored-value access](https://developers.cloudflare.com/secrets-store/manage-secrets/)

R2's conditional writes support offsite archive creation. Core evidence additionally requires pinned object versions, verified bytes, ownership and exact-version cleanup. Its signed references and existing records depend on these semantics. Bucket locks or ETags cannot satisfy that existing contract. The current SQS path renews an in-flight message's visibility and persists a broker-issued publish ID. Cloudflare's documented HTTP pull acknowledgment/retry protocol does not renew a lease in place. Its publisher response, payload limits and plan-specific retention also differ. The code keeps the current SQS contract. [R2 compatibility](https://developers.cloudflare.com/r2/api/s3/api/) · [Cloudflare pull consumers](https://developers.cloudflare.com/queues/configuration/pull-consumers/) · [Queue limits](https://developers.cloudflare.com/queues/platform/limits/)

## Deploy and rehearse the hybrid configuration

1. Start with the complete production values and Terraform inputs already used by the installation. Record the deployed versions, scopes, outstanding jobs, and existing secret, key, bucket and queue references. For local or chart evaluation, generate a separate config with `./zasp --profile local config init` or `./zasp --profile kubernetes config init`, then run `./zasp doctor` with that config. Production Terraform and Helm input files are independent of the CLI's `zasp.env`. The example overlays contain no private values.
2. Install the independent OpenBao release. Configure scoped tokens for each participating workload, verified certificates, KV mount with one retained version, Transit key inventory, off-host unseal material and a tested offsite snapshot. Set the OpenBao chart's client namespace to the actual production namespace. Follow the separate procedure if Nango also moves. [OpenBao server](openbao-vps.md) · [Workload credential projection](openbao-workload-projection.md) · [Nango cutover](independent-nango.md)
3. The hybrid example opts into both provider-managed encryption choices. Its audit queue setting applies only when the base production release already enables audit exports and meets the schema and rollout requirements. Those choices are optional. To retain the deployed KMS configuration, omit the encryption overrides in both places. Substitute the actual credential prefixes and provisioned signing UUID, retain historical KMS pins for readers, and ensure recovery canary inputs are already valid. Set the file variables below to absolute paths. Review the Terraform plan and render the exact Helm release for inspection before rollout. Protect plan files and render output according to their contents.

   ```sh
   umask 077
   EXAMPLES="$PWD/deploy/examples/infrastructure-providers"
   terraform -chdir=deploy/staging plan -var-file="$PRODUCTION_TFVARS" -var-file="$EXAMPLES/hybrid-aws.tfvars"
   helm template zasp deploy/staging/product -n "$ZASP_NAMESPACE" \
     -f "$PRODUCTION_VALUES" -f "$EXAMPLES/hybrid-openbao.values.yaml" > "$PRIVATE_RENDER_FILE"
   ```

4. Prepare the existing AWS permissions, queue/bucket encryption and mixed-history readers before starting new writers. Wait for required deployments to become ready. Rehearse a tenant-scoped OAuth flow, a discovery read, a retained pre-cutover signature, a new signed backup, and an audit message through its work queue. Check the pinned object version, owner, SHA-256 and encryption of a new evidence write. Customer AWS discovery must still assume the separately authorized customer role.
5. Merge the R2 writer example into the backup operator's private config. Configure a distinct read-only recovery identity on a separate machine. Exercise `./zasp backup upload` and `./zasp backup download` on an isolated fixture, then restore the appropriate service using its native procedure. Rehearse replacement-node recovery while the original OpenBao instance and VPS are offline. Keep the trusted receipt and private keys outside the failed environment. [Encrypted archives and recovery](offsite-backups.md)

## Migration and rollback boundaries

| State | Cutover | Rollback or historical access |
| --- | --- | --- |
| Active integrations and OAuth | Inventory source versions, quiesce writers and consumers, finish or expire grants, create KV records at the original scoped names and compare the decoded bytes. Switch API and discovery together. | Reconcile all creates, changes and deletions back to the prior encrypted AWS namespace before switching back. Provider errors do not trigger a search through alternate stores. |
| Recovery signatures | Enable the new verifier before new writers. Archive the key identity and Raft snapshot immediately after creation or rotation. Rehearse one manifest from each signing generation. | Retain original KMS keys, permissions, Transit versions and the correct seal material. Select the old signer for new writes while permitting both recorded authorities for verification. |
| Evidence and queues | Drain outstanding evidence writes, preserve original versions and service-account policies, change encryption in place, and check both the work queue and DLQ. | Retain historical key access for the full retention/redrive period. An older KMS-only reader cannot restore newly written SSE-S3 versions. Moving or re-encrypting signed evidence requires separately migrated, validated references. |
| Backups and databases | Keep several verified generations. Test recovery from a trusted receipt into an empty destination and verify application records, authorization, key versions and service health. | Select the original archive provider explicitly. Preserve old credentials and private keys until their recoverable backups expire. A Helm rollback leaves database migrations and new connection data intact. |

## Verification and cost

The provider workflow distinguishes protocol fixtures from live services. Go fixtures exercise rejected configurations, tenant and credential boundaries, rotation, service failures, signing and encrypted S3 metadata. The backup tests run OpenSSL locally and use simulated object-storage responses. The disposable Docker drill uses real OpenBao over TLS, distinct source and replacement Raft instances, and both KV and Transit while using no customer account. Helm tests render workload identities, network policy and endpoint selection. Live S3 and R2 archive checks are opt-in against isolated buckets; see the exact environment switches in the archive runbook. Check the workflow run for the commit you intend to deploy. A rendered chart or passing fixture does not establish a live EKS, k3s, AWS, R2 or Nango rollout. [CI definition](../../.github/workflows/infrastructure-providers.yml) · [Backup test scopes](offsite-backups.md)

VPS compute can avoid EKS and managed-node fixed costs, while shifting disk durability, upgrades, monitoring, downtime and restore labor to the operator. A single VPS or OpenBao server is a failure domain. SSE-S3 and audit SSE-SQS can reduce customer-managed KMS requests for those writes. Existing signatures, retained encrypted data and unrelated services may still require AWS keys and grants. R2 Standard archives have a storage/operation allowance and no direct internet egress charge under its published pricing. Budget for storage beyond the allowance and upload/read-back operations. SQS already offers a free request allowance. Cloudflare Queues prices operations and limits retention by plan, so broker substitution has no assumed cost saving. [R2 pricing](https://developers.cloudflare.com/r2/pricing/) · [SQS pricing](https://aws.amazon.com/sqs/pricing/) · [Queues pricing](https://developers.cloudflare.com/queues/platform/pricing/) · [KMS pricing](https://aws.amazon.com/kms/pricing/)
