# M0-23 technical proof gate design

Date: August 15, 2026

## Decision

M0-23 is an evidence-only architecture gate. It does not rerun provider,
container, or network proofs and does not create a new runtime. It records one
current decision for each of the fourteen M0 risk boundaries, links retained
evidence for every PASS, and keeps unresolved real-provider requirements
explicitly blocked.

The gate result is **PROCEED WITH BLOCKED PATHS**, not an unconditional PASS.
M1 foundation work may begin because the remaining uncertainties are isolated
to later provider-dependent paths. R-03 continues to block real-AWS IAM parity
and its dependent M1A/M3 claims. R-11 continues to block EKS Fargate strong-
isolation and egress claims. LocalStack, fixture, source-review, or harness-only
evidence cannot advance either blocker.

## Alternatives considered

1. **Dedicated gate record — selected.** Add one strict fourteen-row decision
   table in `docs/decisions/m0-technical-proof-gate.md`, update only risk rows
   whose retained proof evidence is complete, and protect the result with a
   repository contract. This makes the final architecture decision readable
   without weakening the risk register's original proof criteria.
2. **Extend the risk register only.** This is smaller, but mixes original proof
   criteria, changing evidence, blocker consequences, and the aggregate M0
   decision in one table. It is harder to audit and easier to misread.
3. **Rerun every proof.** This adds provider cost and mutation risk without
   improving retained evidence. M0-23 is a decision gate, not a repeat-live
   gate, so this option is rejected.

## Gate record

The decision record contains exactly one row for each ID R-01 through R-14.
Each row has these fields:

- risk ID;
- outcome, exactly `PASS` or `BLOCKED`;
- source proof task or tasks;
- retained evidence reference;
- resulting architecture decision.

Exactly twelve rows are PASS: R-01, R-02, R-04, R-05, R-06, R-07, R-08,
R-09, R-10, R-12, R-13, and R-14. R-03 and R-11 are BLOCKED. The summary is
therefore `12 PASS / 2 BLOCKED / 0 FAIL / 0 unclassified`.

PASS rows must link retained proof reports or exact proof heads. The four risk
rows that still have historical `Not run` text despite completed proof chains
are updated to PASS: R-01, R-02, R-04, and R-05. Existing evidence-backed PASS
rows remain unchanged except where the gate contract needs a complete evidence
reference.

R-03 remains Not run in the risk register and BLOCKED in the gate record until
the reviewed M0-09 real-AWS harness receives its nine isolated two-account
inputs and passes. R-11 remains Not run in the risk register and BLOCKED in the
gate record until M0-18 and M0-19 receive their documented isolated real-EKS
fixtures and pass. Their architecture decisions name the blocked downstream
claims and exact resume conditions.

## Status transition

Starting M0-23 changes the 728-task summary to `701/1/23/3` and M0 to
`27/0/1/23/3`. Completing it changes the summary to `701/0/24/3` and M0 to
`27/0/0/24/3`. M0-09, M0-18, and M0-19 remain Blocked. R-03 and R-11 remain
unpassed. M1-01d remains Pending until M0-23 is committed, pushed, reviewed,
and the exact-SHA Runnable UI gate succeeds.

## Validation

`app/quality/m0-gate-contract.test.ts` parses the source task, risk register,
gate record, tracker, and README. It requires:

- exactly fourteen unique ordered risk rows;
- exactly twelve PASS and two BLOCKED outcomes;
- no PASS for R-03 or R-11;
- exact blocker dependencies and downstream architecture consequences;
- complete evidence references for every PASS row;
- aggregate and M0 status arithmetic equal to 728 and 27;
- no M1 task in progress before M0-23 completes;
- hostile duplicate, missing, extra, outcome, evidence, blocker, and count
  mutations to fail.

The task uses the pinned repository test, typecheck, lint, build, production
audit, whitespace, and redacted secret-scan gates. It performs no Docker,
Kubernetes, cloud-provider, or credential operation.
