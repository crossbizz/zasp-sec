# Staging IAM policy unions: source component

The original M1A-06 acceptance at implementation-plan lines 1278–1281 requires product IAM/IRSA policies to deny unrelated writes. The new verifier evaluates 38 workload role unions containing 41 inline policies against 2,685 independently specified requests. It consumes one complete offline Terraform mock-plan JSON event stream. This is repository source-component evidence; cloud, native and production acceptance remain false. Original728 scope/status counts and production role/policy/trust definitions are unchanged.

The role roster preserves 16 scalar roles, nine runtime, four recovery, three red-team, three attack-lab and three audit-export roles. Only the exact EKS cluster/node and Fargate execution roles are excluded. Disabled authorization/Temporal, compliance, test-reconciler and attack-lab-reconciler roles must have zero instances. API, connectors and audit reader remain separate role identities even where their service-account subject is shared. The web and product canary service accounts have no IRSA role; canary secret synchronization is a separate identity.

The fixture supplies distinct mock identities for 131 resource bindings and closes the 262-resource plan roster. Policies join by actual role ID, including the secondary audit-export secret policies attached to API, writer and publisher. Unknown or ambiguous identities, missing/extra resources, unlisted embedded policies or attachments, unresolved workload managed policies, changed trust, unknown policy values and changed runner deny-all boundary refuse. The current workload roster has zero managed-policy attachments; six explicitly closed infrastructure attachments are outside this workload decision model, not assumed denied.

Request expectations are fixed workload contracts from main.tf, audit_exports.tf and existing session-search assertions; actual Allow statements do not generate expected outcomes. The matrix retains producer/consumer queue splits, runtime archive read-only behavior, discovery/recovery/red-team/attack-lab object namespaces, audit SSE/KMS context requirements, connector versus index session methods, inventory runtime versus schema-initializer methods, secret-only identities and unrelated IAM/S3/SQS/OpenSearch writes across all 38 roles. It preserves legitimate inventory POST delete_by_query and legacy event PUT. Requests include missing/wrong KMS and SSE contexts, foreign keys/queues/buckets/prefixes/index methods, and secondary-policy grants.

The evaluator supports only the existing identity-policy subset: Allow/Deny, Action/Resource string or list, StringEquals/StringLike/ArnLike with the six enumerated source context keys. It validates every statement before evaluating requests, combines all recognized inline policies, applies explicit Deny precedence and refuses unsupported constructs, conditions, JSON duplicate keys and variable expansion. Its finite request matrix is not an exhaustive IAM equivalence proof or an AWS effective-permissions simulator. SCPs, session policies, resource/account policies, deployed role attachment state and deployment identity mapping require separate acceptance.

The existing CI IAM initialization and both predecessor test filters are preserved. The added commands are:

```sh
node --test deploy/staging/iam-policy-union-v1.test.mjs
terraform -chdir=deploy/staging test -filter=tests/iam_policy_union.tftest.hcl -json -verbose -no-color > iam-policy-union.jsonl
node --max-old-space-size=512 deploy/staging/iam-policy-union-v1.test.mjs --plan iam-policy-union.jsonl
node deploy/staging/iam-policy-union-v1.mjs --plan iam-policy-union.jsonl
```

The workflow uses its checksum-verified Terraform 1.15.8 executable and readonly AWS 6.60.0/TLS 4.3.0 lock. The mock profile has offline validation, mocked providers and all optional role flags disabled; it never applies or contacts AWS. No private fixtures or credentials are required by the Node tests. Nonzero test/capture/verifier statuses propagate. The existing 10-minute CI step remains; the verifier refuses inputs above 64 MiB and captured controls use a 512 MiB Node heap. The private evidence supervisor separately enforced 180-second command, 64 MiB stdout, 2 MiB stderr, 128 MiB disk-growth and 2.5 GiB free-space bounds with joined owned descendants; those private lifecycle controls are not represented as CI runtime authority.

Causal evidence preserves the original 11-pass/2-fail queue-fixture predecessor and the independently published two-map correction restoring all 13 cases. Against that corrected baseline, an actual extra inline policy granting audit writer s3:DeleteObject still passes all 13 selected predecessor cases; the new closed-union intake refuses its complete mock plan. Independent pure-model controls and actual captured-plan mutations cover the second existing inline policy, condition removal, extra/local or unresolved attachments, unsupported constructs, duplicate JSON, trust/boundary drift, role aliases, completion/schema errors, exact event/run progress order and unknown/type-masked policy metadata. The metadata controls were first observed failing, then passed after the relevant guards were implemented. Raw mock plans and failed attempts remain retained privately for review; no deployed IAM/SCP/boundary/session-policy success is claimed.
