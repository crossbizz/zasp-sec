# Owned OpenFGA gRPC fallback source correction

This source component corrects the owned runtime helper's internal OpenFGA gRPC address and verifies both its HTTP and gRPC listener ownership. It does not establish actual service readiness, current80 activation, installed worker behavior, native parity, deployment, or release acceptance.

The published helper configured `OPENFGA_GRPC_ADDR=127.0.0.1:0`. The exact official OpenFGA 1.21.0 commit `ab557c5592670c899de35297e7aa067015f06502` creates its internal HTTP-to-gRPC Unix socket beneath `TMPDIR`. Our long private temporary path exceeds Linux's Unix socket pathname limit. When that socket cannot bind, official `cmd/run/run.go` falls back to dialing the configured gRPC address rather than the actual address selected by `net.Listen`. Port zero therefore leaves that fallback unusable. Official `pkg/server/health/health.go` explicitly bypasses authentication for health; adding a bearer token to the health probe is unsupported by that source evidence. Retained official Git-tree/blob verification is in the private review packet.

The existing physical observer verifies that both OpenFGA listeners belong to the same owned process lifetime and socket inode. Both checks run at startup and before and after every health probe and authenticated store/model request. A successful health response becomes readiness only after both subsequent ownership checks succeed.
