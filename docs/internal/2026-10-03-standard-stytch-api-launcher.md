The normal developer API launch command is `npm run api:start`. It runs exactly `go run -mod=readonly ./agentsec-api` from `services/platform`, with `GOTOOLCHAIN=local`; it requires a compatible locally installed normal Go toolchain. It accepts no command arguments. Existing web `npm start`, mounted-secret deployment startup and controlled browser identity fixtures remain unchanged.

At this launch boundary only, trusted parent environment keys `STYTCH_PROJECT_ID`, `STYTCH_SECRET` and `STYTCH_PUBLIC_TOKEN` map to their corresponding `ZASP_` names. Existing prefixed values work unchanged; identical paired values are accepted. Differing pairs or explicitly empty/non-string provided values refuse with a fixed error. Mapping copies the environment without normalizing credential bytes or changing the parent. It performs no provider requests, session creation or identity mutation.

This is configuration plumbing, not a runnable environment or connectivity acceptance. The API retains its full original strict loader and current authorization/service guards. The correct existing-project provider endpoints, webhook secret, provider organization, public origin, separate PostgreSQL identities/DSNs, signing keys and genuine runtime/admission configuration must be supplied explicitly as required. The command does not infer any of them, map DATABASE_URL, or use GITHUB_TOKEN as an application credential. In the observed configured session, the three standard credentials were present but their aliases and multiple other required fields were absent; no credential values were read, written or hashed to prepare this change.

The launcher retains only bounded child output (256 KiB) and emits a fixed launch refusal instead of child output or raw exceptions. Output overflow refuses and stops/joins the owned command. SIGINT, SIGTERM and SIGHUP request owned shutdown; completion and cleanup are awaited before propagating status or signal. These controls do not certify detached arbitrary-descendant containment or protected/native execution.

Private tests exercise the actual module and entrypoint with synthetic credentials and finite process stubs: nine Node controls pass, including fixed argv/cwd/toolchain, conflicting aliases before spawn, missing fields at consumption, caller-argument refusal, exit/signal propagation and secret-safe errors. Targeted ESLint passes. No real Go launch, API startup, provider connectivity, deployment, native admission, release or all-728 completion is claimed.
