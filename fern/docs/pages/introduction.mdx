Zasp is an agent security platform. It answers four questions about the AI agents in an organization:

1. **Which agents exist?** Including the ones nobody registered.
2. **What can each one reach?** Its identities, its tools and MCP servers, its data.
3. **Where is that a risk?** As findings with evidence, and as attack paths.
4. **What can be done about it?** Tests, guardrails, approved fixes and evidence for auditors.

## Agentless

Nothing is installed in your cloud accounts, clusters or repositories.

Zasp reads provider APIs with read-only credentials that you grant. It also reads the logs your providers already keep, such as CloudTrail, Route 53 Resolver query logs and VPC Flow Logs. From those it finds agents that no control plane lists: a Lambda function that calls a model, a role that invoked a model last week, a workload that resolved and reached a model API.

Three add-ons exist for teams that want more than reading. Each is optional.

| Add-on | What it adds | What changes at your side |
| --- | --- | --- |
| [Hosted gateway](/concepts/guardrails-and-gateway) | Inspection of an agent's MCP and model traffic in flight | One address and one token in the agent's configuration |
| [Remediation role](/concepts/remediation-and-approvals) | Two approved changes in an AWS account | A second IAM role with write access to exactly those changes |
| Runtime sensor | Process and network evidence from inside a Kubernetes cluster | Installed software in the cluster |

## What has and has not been run

This documentation says so where something was not run against a real provider. In short:

- The product runs end to end on one machine against an emulated AWS account. The procedure is in the repository under `docs/operations/local-self-test.md`.
- No connector has been run against a real provider account, tenant or cluster.
- The production deployment procedure has been checked as text. It has not been applied to an AWS account.

Each integration page repeats the status of its connector.
